Mini editorial style guide

A short working guide derived from the public-source audit.

Reference topicLook up the rules I use to write and review copy.

Why the wording matters

When a company considers using AI, it needs to know what the tool does, who can use it, and what evidence supports the promise. This proposed style guide shows how I’d help writers answer those questions consistently across launch posts, guides, and research stories.

Start with the Cohere overview and journey map

Rules I’d apply in a review

RuleHow I’d write or review it
Lead with the reader’s decisionName what changed and who can act. For a launch, lead with the workflow and what it enables. For developer content, lead with the task and show the result. For research, teach the distinction before introducing a metric.
Translate the benefit into a mechanismFor Context Focus, say that Rerank 5 can return offsets for relevant passages in ranked documents. Preserve Context Focus as the feature name and introduce relevant_spans when a developer needs to configure it.
Keep scope next to the claimState the product, API surface, model version, region, or access requirement in the sentence where it matters. Distinguish an optional setting, a default, and a preview.
Make comparisons checkableWhen citing a performance number, record the source, benchmark, metrics, comparator, model versions, and date. Attribute findings to the team or study. If those details are unavailable, narrow or hold the claim.
Choose verbs that describe the operationUse returns, ranks, or estimates. A relevance score concerns the match to a query. Researchers’ confidence estimates concern a different question, such as whether an answer is correct.
Write examples people can useShow the default and the edge case. Use sentence case, expand acronyms on first use for broad audiences, and use link text that names the destination. Get technical review for API examples before release.

Keep the guide current

I’d record each new rule with a before-and-after example, the evidence that prompted it, and the channels it applies to. Product names and availability go back to their owners when a release changes them. I’d bring recurring friction to editorial review and update the templates after we agree on a rule.
