Helping users run a valid detector test

I organized detector guidance around the decision a user needs to make before running a test: which inputs produce a result they can interpret?

A definition is only the beginning

Users had to choose a detector, supply the right input, and interpret a result. Definitions varied, examples sat outside the task, and the terminology in the UI and docs sometimes diverged.

I reviewed early builds, engineering specifications, schemas, and docs. I grouped detectors in the navigation, defined patterns for one- and two-input detectors, wrote examples and warnings, and aligned labels with backend fields and documentation.

Make the requirements visible before the test

Illustrative content pattern

What to show for each detector

  1. Tell the user what the detector checks.
  2. Name each required input beside its field.
  3. Give one example that demonstrates a valid test.
  4. Explain the result fields in the terms the reference docs use.
  5. Warn users before a detector change clears entered test data, where that behavior applies.

Use the same rule in the interface, docs, and specification

Some detectors check one input. A faithfulness or groundedness check can require an answer and a source. That difference belongs beside the input fields, where a user can act on it. I defined example and field patterns for both cases, aligned result labels such as “Score” with the reference, and added a warning for actions that clear entered data.

I kept a shared terminology and definition table in GitHub. I worked in weekly review cycles with Design, Engineering, and Product, wrote rationale and acceptance criteria in GitHub issues, and validated changes in a test environment.

What the team carried forward

Teams adopted the detector content patterns across multiple governance features. The shared definitions, naming rules, and example format also gave the team a starting point when adding detectors. Internal QA and support feedback indicated fewer invalid inputs and fewer requests for help with setup.
