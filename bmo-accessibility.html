Case study · BMO

Accessibility copy for account access

I worked on accessibility copy for digital banking, including account recovery and login management. I specified what a control should communicate when a customer can’t rely on the surrounding screen.

Give the action enough context

A visible “Select” button can rely on the option beside it when someone scans the screen. The same button can be ambiguous when it’s read on its own. I worked on the labels for those controls, the surrounding form instructions, and the messages that help someone pick up a task after an error.

Write for the control and the state together

The specifications paired copy with the screen or state where it appears. They documented visible text, accessibility copy, and error messages alongside Canadian English and French variants. That structure let reviewers compare what a person sees with what they need to hear, then check that both languages communicate the same action.

Illustrative example

Repeated controls in a list of options

Visible label
Select
Accessible label
Select email as your contact method
Validation message
Choose a contact method to continue.

When reading the controls in sequence, check whether each one identifies the option it applies to. Check that the validation message names the action the customer can take next.
